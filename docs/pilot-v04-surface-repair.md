## Surface-only audit

The public approval convention defines the target label. Its apparent 100 percent agreement with that label is a reference, not independent predictive validation. A comparison that merely asks whether a heuristic exceeds it would be vacuous.

Fit simple selectors on the 24 development histories and evaluate the frozen selectors on 24 disjoint review histories. Also report the prospectively selected six exported examples, without selecting models or thresholds on them. No final-test cases or model outputs enter this audit.

The target is a direct, currently binding approval of the target field. Report two prespecified populations.

1. All non-registration records. Dates may carry legitimate information about expired versions, so this is a broad diagnostic.
2. Accepted review events in the current version. This tests genuine approvals against apparently accepted but unauthorised or insufficiently scoped approvals. Some small histories have only positive examples here. Report those groups as undefined for balanced accuracy, rather than inventing negative examples.

Predictors are date, day of month, clock hour, minute within the hour, clock minute of day, exact generic comment and relative position in the delivered list. They cannot read event type, decision, actor, authority roster, reviewed fields, version, context, proposed value, latent world, case type or counterfactual audit. Population selection may use public event semantics but those fields are not predictors.

Prespecify equality/date-threshold selectors, day/hour thresholds, minute-of-hour thresholds from 0 through 58, clock-minute-of-day thresholds at fixed quarter-hour boundaries, exact-comment selectors and position quartiles, with both polarities and constant baselines. Select each family winner and one overall winner on development history-macro balanced accuracy only, with deterministic tie-breaking. Freeze them before review evaluation. Report confusion counts, precision, recall, specificity, pooled and history-macro balanced accuracy, group counts and undefined denominators. Do not substitute raw accuracy for balanced accuracy when only three approvals occur among many records.

Report cross-class feature overlap and whether a feature or a fixed joint surface signature exactly separates the observed labels. Check constructive shared comment and temporal support for hard negatives, mixed delivered order and absence of the former fixed timestamp/comment scheme. A perfect held-out selector in the current accepted-review population requires investigation before treating materials as ready. Nonperfect elevated accuracy is reported, not automatically equated with chance or with proof that all shortcuts are gone. Legitimate temporal validity signals are not counted as a defect merely because they predict some labels in the broad population.

The audit documents the tested shortcuts only. It does not establish the absence of every exploitable textual or structural cue. Its measurements are separate from the inference headroom criterion.

## Apparent-conflict resolution

Add a secondary subtype for an apparent contradiction resolved by majority or recency. Apply it only to the three decided task types where false approval promotion can cause a contradiction. Distinguish a registered, observable match to a majority/latest-record heuristic from a confirmed explanation of the model's reasoning.

Define the heuristic rules and tie handling before reading model outputs. Derive the candidate configurations and source dates solely from public records, retaining their provenance. Compare wrong executable effects or adopted guidance against those predictions. Ties, insufficient evidence, invalid preparations and ambiguous matches remain visible. A matching outcome alone does not prove that the model used majority or recency. Explicit rationale can be recorded for later human attribution review.

For each complete current context, collect current binding target approvals and publicly recoverable configurations from the six manipulated record types. Each visible record contributes at most one vote. A copy is another visible record, with its origin retained in the audit. Majority means the most frequent binary target configuration. A tied count is unresolved. Recency means the configuration at the latest visible record timestamp, including the forwarding time for a forwarded record. Opposing configurations at that same latest timestamp are unresolved. Registries and technical logs cast no vote. A manipulated record without a recoverable target configuration contributes no invented vote and leaves that context's heuristic comparisons unassessable.

An observable error match requires a decided task type, a unique oracle configuration at the evaluated context, both configurations present among the apparent votes at that context, a wrong unambiguous heuristic prediction and the same wrong executable or retained effect. There is no virtual oracle vote. This conservative marker does not capture contradictions inferable across contexts when the evaluated context itself has only one observed configuration. Preserve that limitation and any unassessable comparisons.

Show the subtype by task type and for C1 and C2 preparation, preserving the raw artifacts and any missing assessments. It may overlap an existing scope/content error and must not be counted as another independent failure. Headroom, conservative attribution and fixed denominators remain unchanged.
