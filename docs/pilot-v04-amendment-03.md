This is a change to the registered inference problem, not a cosmetic difficulty adjustment. All revised examples require a new material review. Preserve the initial six examples, their pending approval record and the completed offline run.

For the old fixtures, compare the oracle before and after removing instructional sentences, holding the old hypothesis class fixed. Each approved field observation constrains one context in one version. Broader consequences must follow from the public hypothesis class. A preference, rejection, unreviewed field or unauthorised revision supplies no approved assignment under this deliberately limited synthetic convention. This limitation remains explicit. The pilot does not yet learn how much informal feedback should count as evidence in real organisations.

## A genuinely structured hypothesis class

The current four independently assigned binary cells permit all sixteen Boolean functions. Saying that a requirement depends on neither, one or both dimensions does not narrow this class. With all sixteen functions, an unseen cell remains free regardless of evidence elsewhere.

Use two binary contextual predicates, x and y, and two field configurations. Zero denotes the configured baseline and one the available alternative. In each registered version, the permitted requirement is one of fourteen distinct functions.

* Always baseline or always alternative.
* One literal, x, not x, y or not y.
* A conjunction of one literal from each dimension.
* A disjunction of one literal from each dimension.

Deduplicate identical truth tables. This includes conditions on neither, one or both dimensions, with unknown polarity. It excludes only XOR and XNOR, the two checkerboard patterns. Publish the complete class definition in the shared task semantics received by all arms. Do not expose the selected world policy, intended regime or evaluator candidate list.

This class is a restricted synthetic model. Its exclusions are not established facts about enterprise requirements. A test of reliable inference under these exclusions must not be presented as unrestricted discovery of latent requirements. Fully crossed evidence outside the class is a material inconsistency and stops generation. No shortest-rule preference, majority vote or hidden prior selects among compatible hypotheses.

The neutral version contract declares one class member per registered version. A review constrains only the member indexed by its recorded version and valid authority interval. No cross-version coupling is part of the class. Keep this public structural assumption even after removing the instructional warning about old evidence. Time validity and provenance therefore remain interpretation tasks under declared semantics, not discoveries of those semantics.

Why this class is preferred for this pilot

* A monotone six-function class would additionally disclose the polarity of nominal context dimensions.
* A conjunction-only class would exclude alternative sufficient triggers.
* Fourteen functions retain both forms and unknown polarity while requiring minimal changes to the existing two-dimensional contracts.

In this class, a new cell can become identifiable from three distinct observed cells. That gain comes from excluding the checkerboard alternatives. It must be named in the report, rather than attributed solely to model reasoning.

| Type | Current authorised observations | Diagnostic context | Oracle conclusion |
| --- | --- | --- | --- |

### Supplement 1. Counterfactual relevance of manipulated records

For each history, audit every record of each manipulated type actually present. The six types are forward, old approval, unauthorised revision, rejected opposite artifact, target-field preference and approval without the target field. Technical recovery logs are counted separately and are not one of these six approval-promotion interventions. An absent type has no fabricated zero-denominator success claim.

The counterfactual promotes exactly one record's publicly recoverable target-field configuration to a binding current-version observation at its apparent context. Preserve every genuine observation. For a forward, read the referenced artifact but use the forwarding destination. For an old approval, use its context with the current version. For an unauthorised revision, rejection, preference or unreviewed target field, promote the visible proposed or artifact configuration. Do not invent a value, remove counterevidence, mutate the real history or use the hidden world. Log the selected public value, context, provenance and precise promotion for each record.

Compute the compatible set again from public evidence with this single added constraint. Report a nonempty set with changed diagnostic or control action as an action flip. Report an empty set as a contradiction, never as a flip. Distinguish unchanged constraints, narrower compatible sets with unchanged actions, and changes from unresolved to resolved retention. No empty-set `all()` result may become a warranted action.

Every present manipulated type in an unidentifiable history must have at least one action-flipping record. In the other three task types, every present manipulated type must have at least one contradiction-producing record. Neutral records do not fulfil either requirement. Material generation stops if any required type lacks a qualifying record. Report counts by type and history and identify the qualifying examples in the human-review export.

This distinction is mathematically necessary. Adding a constraint can only shrink the compatible set. Once all compatible policies agree on a task action, no nonempty subset can reverse it. The four templates have respectively 1, 3, 1 and 4 current policies. Exhausting the eight possible single-cell binary observations gives 0, 0, 0 and 2 possible action flips. Contradictions number 4, 2, 4 and 2. These counts are independent of model performance. Counterfactual qualification demonstrates decision relevance or conflict potential, not that a model will actually make the corresponding mistake.

The qualifying records must be constructed prospectively from the slot's public evidence and counterfactual audit. Do not search model outputs or redraw seeds for desired errors. The counterfactual audit is evaluator material and must never enter model payloads.

## Oracle and measurement changes

Keep the independent public-evidence oracle and all three truth objects. Replace enumeration of all sixteen functions with enumeration of the declared fourteen. Do not supply the generator's world or intended label to the oracle. Check compatibility and the intended regime independently after generation.

The primary outcome, fixed denominators, conservative error taxonomy, headroom criterion and candidate-error secondary outcome remain unchanged. Report the four task types separately. The new measurement distinction is supported use in an observed context versus warranted transfer to an unobserved combination.

Add deterministic preparation-level scope coverage across the four registered current-version combinations. Compare the combined effect of retained adopted guidance against all oracle-supported changes and against cells where a change is unsupported. This exposes missing warranted scope as well as excessive scope without extra model calls. Score equivalent decompositions by their combined consequences. Do not call an individually narrow valid rule erroneous simply because another candidate covers the remaining scope. Missing preparations and undefined coverage remain explicit.

Keep C1 and C2 candidate errors separate, independent of final correctness. Candidate evidence claims require a separate check from correct rule consequences. Correctly rejected and unresolved candidates are not adoption errors. No new secondary measure enters the headroom criterion.

### Supplement 2. Direction of transfer errors

Report unsupported transfer and missed warranted transfer separately. Unsupported transfer changes an unobserved current-version context where the compatible policies do not unanimously justify the change. Missed warranted transfer leaves an unobserved context unchanged despite unanimous support for change. Contradicting a directly observed requirement is a separate observable scope error. Determine the direction from executed effects or retained adopted guidance, not a declared label alone.

Report these effects per task type and separately for C1 and C2 over all four current-version context cells. Combine equivalent rule decompositions before scoring coverage. Unresolved or rejected hypotheses are not treated as adopted changes. Missing or unrenderable preparations are not error-free preparations. Technical failures and semantic attribution limits retain the existing conservative handling.

Also report an adoption pattern consistent with selecting a simplest compatible hypothesis. Complexity belongs to the Boolean function, not to the number of emitted rules or its wording. Constants have complexity zero, one-literal functions complexity one, and the remaining conjunctions/disjunctions complexity two. Preserve all tied minima. Flag the pattern only if multiple compatible functions disagree, combined adopted effects match a minimum-complexity compatible function, and an unsupported extension occurs. It is an observable association, not proof of the model's motivation. A simple hypothesis explicitly retained as unresolved is not an error. This marker may overlap unsupported transfer and must not be added as another independent error count.

Neither direction tags nor the simplicity marker change the headroom criterion or automatically turn provisional attribution into confirmed content error.
