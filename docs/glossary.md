# Glossary for pilots v0.4 and v0.5

Read the [v0.4 guide](../pilots/v04/GUIDE.md) or [v0.5 README](../pilots/v05/README.md) first. This glossary explains the study vocabulary, not claims about real organisations. The source column points to the public methods, reports and verification guidance. Original protocols and amendments are indexed in [provenance](provenance.md).

## Study design and procedures

| Term | Plain-English meaning and differences between pilots | Further reading |
| --- | --- | --- |
| Arm | A procedure being compared on the same task design. Arms have different preparation costs, so sharing a model and evidence pool does not mean equal computation. | [v0.4 arms](methods.md#pilot-v04); [v0.5 arms](methods.md#pilot-v05) |
| A, no history | The agent receives the current task, initial configuration and public execution contract, but no historical evidence. Its history-warrant score is not comparable in v0.4; v0.5 uses the same executed-field primary metric for all arms. | [v0.4 arms](methods.md#pilot-v04); [v0.5 measurement](methods.md#measurement) |
| B, direct use | The agent reads historical evidence when producing each task output. v0.4 supplies the full history; v0.5 selects records deterministically when the history exceeds the input budget. | [v0.4 arms](methods.md#pilot-v04); [v0.5 arms](methods.md#pilot-v05) |
| C, direct adaptation | The agent prepares reusable guidance from history, then receives applicable guidance for each future task. v0.4 uses two preparation calls; v0.5 processes chunks before a final consolidation. | [v0.4 arms](methods.md#pilot-v04); [v0.5 arms](methods.md#pilot-v05) |
| C1 and C2 | C1 constructs candidate guidance and C2 reviews or consolidates it. v0.4 has one of each per history; v0.5 can have several C1 chunk calls before C2. | [v0.4 candidate errors](methods.md#measurement); [v0.5 arms](methods.md#pilot-v05) |
| D, grounded reflection | In v0.5 this specific procedure proposes a register of possible rules, queries records to distinguish them and converts the surviving hypotheses into guidance. v0.4 has no D arm; v0.5 does not test every possible form of grounded reflection. | [v0.5 arms](methods.md#pilot-v05) |
| Hypothesis register | D's explicit list of candidate rules, their status and cited evidence. It can omit valid possibilities, which is the central failure diagnosed in v0.5. | [v0.5 arms](methods.md#pilot-v05); [failure analysis](../pilots/v05/DIFFICULTY_MAP_REPORT.md#why-d-falls-short) |
| D-final | D's last preparation call converts its register into candidate guidance for task execution. It is not a separate experimental arm or a call that sees the future tasks. | [v0.5 arms](methods.md#pilot-v05) |
| Deterministic retrieval | A fixed algorithm selects records without another model call. v0.5 B prioritises registrations and accepted reviews of the target field, then context matches and recency; this does not itself establish reviewer authority or validity. | [v0.5 arms](methods.md#pilot-v05) |
| History / work evidence | A synthetic collection of registrations, reviews, outputs and other records available before future tasks. It contains both binding evidence and records that do not justify a requirement. | [v0.4 materials](methods.md#pilot-v04); [v0.5 evidence](methods.md#evidence-and-warrant) |
| Task family | A fictional work setting used to express a requirement, such as human resources (HR), sales, retrieval or reporting. These are placeholder families, not validated samples of those professions. | [v0.4 materials](methods.md#pilot-v04); [v0.5 tasks](methods.md#pilot-v05) |
| S0 to S5 | v0.4 settings for base evidence, raw artifacts, volume and noise, dependence, change over time, and their combination. They are small descriptive contrasts, not isolated estimates of causal effects. | [v0.4 materials](methods.md#pilot-v04); [amended histories](methods.md#pilot-v04) |
| K-S, K-L, U-S, U-L | v0.5 crosses known relevant attributes (K) or unknown relevant attributes (U) with small (S, 24 records) or large (L, 240 records) histories. Every history still contains 12 binding approvals. | [v0.5 settings](methods.md#pilot-v05) |
| Known-2 / unknown-6 | In known-2, the two relevant attributes are named; in unknown-6, the relevant pair is not disclosed among six visible binary attributes. This changes the public rule class from H14 to H134. | [v0.5 rule class](methods.md#evidence-and-warrant) |

## Evidence, rules and the oracle

| Term | Plain-English meaning and differences between pilots | Further reading |
| --- | --- | --- |
| Baseline / alternative | The baseline is the agent's initial configuration; the alternative changes the target field. The alternative can add or remove a field, so a Boolean value of 1 must not be read as always meaning inclusion. | [v0.4 truth objects](methods.md#evidence-and-warrant); [amended oracle](methods.md#measurement) |
| Binding approval | A review counts as evidence only if it is accepted, its reviewer is authorised, it falls within the registration's validity interval, and it covers the target field. The convention is supplied to the agents, not discovered by them. | [v0.4 amendment](methods.md#evidence-and-warrant); [v0.5 evidence](methods.md#evidence-and-warrant) |
| Distractor / nonbinding record | A record may resemble useful evidence without authorising a requirement, for example a preference, an unauthorised change or an approval of another field. Technical failures are also included, but their presence alone does not show that models are misled by them. | [v0.4 evidence](methods.md#evidence-and-warrant); [v0.5 evidence](methods.md#evidence-and-warrant) |
| Literal | A test of an attribute value, such as recipient equals internal, or recipient equals external. Both values are allowed in the intended rule class; v0.5's public wording did not make that explicit enough. | [v0.5 rule class](methods.md#evidence-and-warrant); [reported specification gap](../pilots/v05/DIFFICULTY_MAP_REPORT.md#why-d-falls-short) |
| H14 | The class of 14 Boolean rules over two binary attributes after excluding the two checkerboard patterns, exclusive OR (XOR) and its complement (XNOR). The restriction is supplied and is what permits some unseen combinations to be resolved. | [v0.4 structured class](methods.md#evidence-and-warrant); [v0.5 rule class](methods.md#evidence-and-warrant) |
| H134 | The v0.5 class over six binary attributes, with each rule using at most two attributes in the permitted H14 forms. Its 134 distinct rules comprise two constants, twelve literals and 120 conjunctions or disjunctions. | [v0.5 rule class](methods.md#evidence-and-warrant) |
| Compatible function | A rule in the public class that agrees with all binding observations. Several rules can remain compatible while predicting different actions on a future task. | [v0.4 structured class](methods.md#evidence-and-warrant); [v0.5 rule class](methods.md#evidence-and-warrant) |
| World function / world compliance | The world function is the generator's hidden rule; world compliance asks whether output matches that rule. It differs from what the available evidence warrants, because the hidden truth may not be identifiable. | [v0.4 truth objects](methods.md#evidence-and-warrant); [v0.4 results](../pilots/v04/DIFFICULTY_MAP_REPORT.md#decisions-and-downstream-outcomes) |
| Warrant oracle | A deterministic reference calculation filters public evidence using the supplied conventions and enumerates compatible rules. It does not use the generator's intended regime to decide whether an update is justified. | [v0.4 truth objects](methods.md#evidence-and-warrant); [amended oracle](methods.md#measurement) |
| Warranted | An action is warranted when the admissible evidence and public rule class justify it at the evaluated context. A lucky match to the hidden world is insufficient. | [v0.4 oracle](methods.md#measurement); [v0.5 measurement](methods.md#measurement) |
| Scope / scope probe | Scope states where a rule applies, including workflow, version and context; a scope probe checks its behaviour at a context or boundary. Declared-rule scope enters v0.4's primary score but is secondary in v0.5. | [v0.4 measurement](methods.md#measurement); [v0.5 measurement](methods.md#measurement) |
| Counterfactual material check | A v0.4 check deliberately treats a nonbinding record as valid to see whether it could matter. Ambiguous histories must allow an action flip; decided histories require a contradiction, which is not an action flip. | [v0.4 supplement](methods.md#pilot-v04) |

## Tasks, scores and interpretation

| Term | Plain-English meaning and differences between pilots | Further reading |
| --- | --- | --- |
| Diagnostic / control | A diagnostic tests whether the evidence supports a change or retention in the studied context; a control checks inappropriate extension beyond the authorised scope. Controls are reported separately and do not enter diagnostic denominators. | [v0.4 task mix](methods.md#pilot-v04); [v0.5 tasks](methods.md#pilot-v05) |
| Observed-context change / retention | The future task uses a context already supported by binding observations and requires either the alternative or the baseline. v0.5 includes both per history; v0.4's resolved-retention diagnostic instead requires transfer. | [v0.4 task mix](methods.md#pilot-v04); [v0.5 tasks](methods.md#pilot-v05) |
| Transfer | Applying a justified conclusion at a context combination not observed in the binding evidence. Both pilots test transferred change; v0.4 also tests transferred retention. | [v0.4 task mix](methods.md#pilot-v04); [v0.5 tasks](methods.md#pilot-v05) |
| Unidentifiable task / unresolved evidence | Compatible rules disagree about the required action at the task context, so these pilots require retaining the baseline. That decision does not prove the baseline true; it is distinct from an unresolved failure cause, where the reviewer cannot attribute why an error occurred. | [v0.4 task mix](methods.md#pilot-v04); [v0.5 rule class](methods.md#evidence-and-warrant) |
| Hard task | v0.5 shorthand for transferred change or an unidentifiable case. Each setting has two of each, constructed so that simple similarity can mislead. | [v0.5 tasks](methods.md#pilot-v05) |
| Headroom | Room for an added method to improve on a strong baseline under a specified decision rule. v0.4 requires C to score at most 70 percent and at least 60 percent of its failures to be confirmed content errors; v0.5 instead checks whether the better direct arm solves every hard calibration task in every setting. | [v0.4 taxonomy and gate](methods.md#measurement); [v0.5 calibration gate](methods.md#measurement) |
| Keep floor | The score reached by always retaining the initial configuration, regardless of evidence. In v0.5 it is 6 of 12 diagnostics per setting, from four observed retentions and two unidentifiable cases. | [v0.5 primary outcome and erratum](../pilots/v05/DIFFICULTY_MAP_REPORT.md#primary-outcome) |
| Registered / post hoc | Registered measures and decision rules were specified before their relevant evaluation; post hoc analyses were added after seeing outcomes. v0.4's executed-field comparison is post hoc, whereas v0.5 registers executed fields as its primary outcome. | [v0.4 correction](../pilots/v04/DIFFICULTY_MAP_REPORT.md#decisions-and-downstream-outcomes); [v0.5 measurement](methods.md#measurement) |
| Content / mixed / unresolved attribution | Content attributes an error to substantive inference; mixed combines substantive and other causes, and unresolved leaves the cause open. v0.4 counts only confirmed content errors in the conservative headroom numerator, while all failed diagnostics stay in its denominator. | [v0.4 error taxonomy](methods.md#measurement) |
| Baseline-polarity inversion | The agent swaps the meaning of the baseline and alternative while reasoning about the rule. This is the unresolved v0.4 S4 pattern; v0.5 D's incomplete rule enumeration is a different failure. | [v0.4 failure causes](../pilots/v04/DIFFICULTY_MAP_REPORT.md#failure-causes-and-headroom); [v0.5 D analysis](../pilots/v05/DIFFICULTY_MAP_REPORT.md#why-d-falls-short) |
| Surface shortcut | A superficial cue, such as a timestamp or repeated comment, that separates binding records without applying the approval convention. The audits test specified heuristics only and cannot exclude every shortcut. | [v0.4 material checks](methods.md#pilot-v04); [v0.5 material revisions](../pilots/v05/README.md#what-happened) |
| Amortisation | Spreading preparation cost across later tasks that reuse its guidance. v0.4 projects conditional token break-even; v0.5 reports measured token cost across four tasks, not monetary return or enterprise savings. | [v0.4 accounting](methods.md#measurement); [v0.5 measurement](methods.md#measurement) |

## Execution records

| Term | Plain-English meaning and differences between pilots | Further reading |
| --- | --- | --- |
| Calibration / contract test / main run | Calibration tests the registered difficulty gate; a contract test checks transport and output format; the main run supplies the reported comparison. Incomplete calibration attempts and technical tests must not be pooled with the main result. | [v0.5 procedure](methods.md#pilot-v05); [v0.4 execution](../pilots/v04/DIFFICULTY_MAP_REPORT.md#registration-and-execution) |
| Seal / manifest / source binding | A manifest lists file hashes; a seal or binding records the exact files associated with a run or approval. It verifies identity, not scientific validity, and requires the original files when published copies have been sanitised. | [v0.4 sealing](reproducibility.md#verification-boundary); [v0.5 integrity](reproducibility.md#verification-boundary) |
| FHGenie | The institutional model gateway used for the completed v0.4 and v0.5 runs. Both used DeepSeek-V4-Flash-0731 with high reasoning; v0.4's earlier gpt-6-sol attempt failed in transport before any usable answer. | [v0.4 model and execution](../pilots/v04/GUIDE.md#4-what-happened); [v0.5 model](../pilots/v05/README.md#methods-called-arms) |
