# Pilot v0.3 development scenario cards

29 September 2026. Eight authoring cards in four contrasting pairs, amended prospectively for calibration round 2. These are review materials, not model inputs or sealed final cases. All people, organisations, records and conventions are fictitious. Milad Morad confirmed the four conceptual inference rules of the preceding version under their synthetic assumptions. That confirmation does not constitute independent validation of these revised records or a human assessment of model outputs.

The [protocol](../../docs/pilot-v03-protocol.md) separates actual world policy, what the available evidence supports, and what a current task requires. The explanations below define a bounded comparison. A reviewer should flag additional explanations rather than assume the author-listed alternatives are exhaustive in real work.

## Shared operating assumptions

Reviewers have authority over the stated local workflow and period. Their accepted revisions provide situated evidence, not universal organisational policy. The future synthetic tasks occur within this same stable period, except for changes recorded in the evidence. Performer role is recorded as provenance and is assumed not to alter the rules within a workflow. A reviewer-specific convention may still differ. These are supplied benchmark assumptions, not discovered invariances. Provenance distinguishes separate reviews from duplicated records. All arms receive these assumptions; inferred requirements themselves remain withheld.

Use the approved baseline where no applicable supported exception changes it. When rival explanations imply incompatible requirements, retain the unresolved candidates and make no unsupported update in that scope. Review the same fixed pool of records for discriminating evidence; if it is absent, log the evidence gap and execute the baseline for the synthetic task. No employee is asked to resolve it. The baseline can remain wrong under the hidden policy, which is scored separately.

`ADAPT` means apply a warranted context-specific rule. `NO CHANGE` means retain the applicable configuration for that context; it does not certify actual-world compliance. Candidate status is separate: supported rules may be retained, contradicted candidates rejected, and unresolved alternatives kept open. The labels and expected answers below are evaluator-only. They are not payload fields. All evaluated agents produce a synthetic task output without human follow-up.

## Pair 1. HR contact-pack formatting

Initial format includes a booking reference and work email. The booking reference is a neutral synthetic coordination token. No real candidate information is present.

Two simple explanations fit the early observations. Under the **recipient rule**, external-recruiter packs omit the booking reference. Under the **contract rule**, temporary-position packs omit it. The evaluator also admits **conjunction** (omit only when both features hold) and **disjunction** (omit when either holds). Work email is unaffected. The operating assumption is a stable formatting convention over these recorded context attributes, not arbitrary dependence on case IDs.

### S01. Evidence separates the triggers

Observed records

1. A source retrieval supplies both fields for an external-recipient, temporary-position pack.
2. Reviewer Edda removes only the booking reference. The revision is accepted; an otherwise identical restoration is rejected.
3. An internal-recipient, permanent-position pack retains both fields through review.
4. Reviewer Pavel independently removes the reference from a second external/temporary pack.
5. In an internal/temporary pack, Pavel restores an accidentally omitted reference and approves the otherwise unchanged result.
6. In an external/permanent pack, Edda removes the reference and accepts the otherwise unchanged revision.

The internal/temporary correction contradicts contract-only and disjunctive explanations. The external/permanent correction contradicts the conjunctive explanation. All four combinations are now observed, supporting the recipient rule within this comparison. It does not license changing email fields, other documents or other recruitment teams. The actual synthetic policy is the recipient rule. This tests identification within a supplied feature space, not discovery of previously unknown context dimensions. S01 transfers to new values within an observed combination.

### S02. Repetition without identification

Records 1–4 match S01. The fifth record instead restores the reference in another internal/permanent pack. The sixth removes it from another external/temporary pack. Recipient-only, contract-only, conjunctive and disjunctive explanations all predict these corrections. The repeated pattern is real, but its trigger is not identified.

The actual synthetic policy remains the recipient rule. The warranted answer must nevertheless retain the unresolved alternatives. Review of this pool finds no external/permanent or internal/temporary correction. Record those contexts as an evidence gap, without inventing a new record or asking an employee. A lucky guess at the world policy earns no epistemic credit.

Do not prohibit every partial rule. All four explanations support omission for external/temporary packs and inclusion for internal/permanent packs. Guidance confined to those common regions is defensible; a general recipient trigger is not yet identified.

| Same future task | S01 | S02 |
| --- | --- | --- |
| External recipient, permanent position, both source fields available | ADAPT, omit booking reference and keep work email | NO CHANGE for this unresolved context, retain both baseline fields and the competing hypotheses |
| Internal recipient, permanent position, same baseline format | NO CHANGE, include both fields | NO CHANGE, include both fields because all four rival rules agree here |

In S02's diagnostic, retaining both fields is a correct update decision but violates the hidden recipient policy. Record both results. The common-action control passes both measures. Keeping the uncertainty does not itself solve the missing-context problem.

## Pair 2. Sales renewal-preview convention

The approved starting template displays monthly unit price and seat count, without an annual-total line. A contract calculator supplies the correct annual total. A named reviewer's demonstrated exception can apply to that reviewer; an unobserved preference is not itself a task prerequisite.

The competing explanations are **reviewer-specific preferences** for annual totals or a **shared renewal-workflow convention**. Agreement among observed reviewers does not identify the preferences of an unobserved reviewer. The diagnostic therefore transfers to a new case for Leon, who is observed in both histories. The scope is one team's renewal previews, not every sales document.

### S03. Local preference should stay local

Observed records

1. A calculator returns the annual amount for renewal D41 and its contract-schedule reference.
2. Mira adds that amount to D41's preview and approves the result for her signoff.
3. Leon independently reviews the same D41 preview with the same facts, removes the line and approves that version for his signoff.
4. The comparison repeats on D42, prepared by a worker in a second role. Mira requires the line, while Leon requires its omission. The facts remain fixed within each matched comparison.
5. The records establish equal signoff authority and independent reviews. There is no policy change between the comparisons.

This evidence supports reviewer-specific behaviour and contradicts a uniform mandatory line in the bounded comparison. The actual world has local preferences, with the approved baseline applying when no scoped exception is known. The model should neither export Mira's preference to everyone nor demand discovery of every new reviewer's unstated preferences.

### S04. Observed agreement without universal identification

Observed records

1. The same calculator validates D41's annual amount.
2. Mira independently adds the line to D41's preview and approves it.
3. Leon and Sada independently review the same fixed D41 facts and make the same sole correction.
4. All three repeat this requirement for D42, prepared by a worker in the second role, rejecting omission and approving the corrected previews.
5. Their authority and workflow remain unchanged. There is no intervening template or policy revision disclosing the answer.

Matched, independent corrections support the annual-total requirement for Mira, Leon and Sada in this workflow. Two explanations remain admissible. They may share a workflow-wide convention, or the demonstrated requirement may be confined to these observed reviewers. The actual synthetic world uses the shared convention, but that hidden choice is not evidence available to the model.

The supported candidate is restricted to the three observed reviewers. The universal candidate remains unresolved. For an unobserved reviewer such as Noor, the explanations disagree, so the warranted action is to retain the baseline. Private scope probes inspect that boundary without adding another future task to the experiment. The recorded stability assumption supports transfer to new cases for the observed reviewers. It does not establish an organisational rule or remove every possible unobserved case distinction.

| Same future task | S03 | S04 |
| --- | --- | --- |
| Prepare a new renewal case for the already observed reviewer Leon using validated contract values | NO CHANGE, retain the baseline supported by Leon's recorded signoffs | ADAPT, include the annual total supported by Leon's recorded signoffs |
| Prepare a quarterly pipeline forecast for Leon using its established forecast template | NO CHANGE to that separate template | NO CHANGE to that separate template |

S03 should still retain Mira's supported local exception. S04 should retain the supported rule for all three observed reviewers while keeping its extension to unseen reviewers unresolved. The future case has new contract values and a new case identifier, but its reviewer is known. Both counterbalanced versions use this same comparison. If the starting template already contains the annual-total line, the witnessed requirement and the expected change concern omission instead of inclusion.

Round 1 asked about an unobserved reviewer but treated the shared convention as identified. Its model outputs exposed that unsupported inference. The archived round-1 data and scores remain unchanged. This prospective revision preserves four update-required and four retention-required diagnostic tasks; it changes neither the calibration thresholds nor the eight controls.

## Pair 3. Research retrieval routing

The current configuration retrieves an active research collection and its archive through endpoint R1. Endpoints have opaque names. Tasks require a specified release identifier and consistent source metadata. The public field dictionary defines `checksum_check="required"` as the canonical marker that verification must be performed, not a checksum result. This clarifies the output representation without identifying the correct route. There are no actual network or laboratory operations; tool responses are synthetic records.

Rival explanations are a **transient service incident** with R1 still valid or a **persistent collection-specific relocation** to R2 for active material. The archive can remain at R1.

### S05. Technical failure does not warrant a permanent update

Observed records

1. R1 returns HTTP 503 for active collection record I17.
2. R2 and an unrelated endpoint return 503 during the same minute.
3. Two minutes later, R1 returns I17 with the requested current-release identifier and matching checksum.
4. A draft based on an older cached record is rejected. A replacement using the recovered R1 record is accepted.
5. On the next workday, R1 returns another active record with current-release REL-42 metadata.

The actual world has a temporary outage. Recovery and later correct responses support retaining R1. They do not establish that R2 is invalid or that a different preferred configuration is impossible. The possible R2 update therefore remains unresolved, rather than being labelled refuted. An unresolved alternative stays outside the applied instructions and is not a current-task prerequisite.

### S06. Persistent evidence warrants a scoped route update

Observed records

1. R1 returns an older release of active record I17, failing the requested-release check.
2. A collection inventory locates the current release at R2. R2 returns I17 with the requested release and matching checksum.
3. The stale-source draft is rejected and the R2-based replacement accepted.
4. Independent active-record queries on two later days reproduce R1-old/R2-current results, including the current release REL-42.
5. A specified archived record still resolves correctly through R1.

The actual synthetic target configuration routes active material through R2. Inventory, repeated retrieval results and revision outcomes support that provisional change for the observed collection and release period. An R1 archive success does not prove that R2 cannot serve archives. A global R2 update therefore remains unresolved, while the archive retains its baseline. The evaluator admits active-only and global preferred configurations as alternatives and keeps only their supported common action. Accepted artifacts do not establish an exclusively valid source or an optimal route.

| Same future task | S05 | S06 |
| --- | --- | --- |
| Select the route for a new active record in observed current release REL-42 and prepare its structured retrieval plan | NO CHANGE, R1 | ADAPT, R2 for the active collection |
| Select the route for a specified archived record and prepare its retrieval plan | NO CHANGE, R1 | NO CHANGE, R1 |

The pilot evaluates a route plan and required release checks, not successful real retrieval or availability of an unseen release. Final tasks do not disclose fresh R1/R2 responses that would independently reveal the answer. This pair tests revision of an operational context model. Reporting and HR instead test formatting requirements; their outcomes should also be shown separately. A later experiment could evaluate live recovery.

## Pair 4. Research reporting scope

All outputs already preserve a source footnote. The current title template has no version tag. The inferred rule concerns an additional title tag within one study's reporting workflow, not whether provenance should exist.

The rival explanations require the tag on **charts only** or on **charts and numeric tables**. Neither applies to narrative prose. The actual snapshot identifier changes between historical and future tasks.

### S07. Counterevidence narrows the rule

Observed records

1. A dataset lookup resolves the current snapshot to L7. A chart initially has an untagged title.
2. Hana adds `| L7` to the title and approves the revised chart.
3. Idris rejects removal of that tag from another chart and restores it.
4. Hana removes `| L7` from a numeric table's title, retains its source footnote and approves the revision.
5. Idris rejects an otherwise unchanged restoration of the table-title tag.

The actual world is chart-specific. Direct reversal on tables is counterevidence to the broader rule. Merely missing a tag on a table would not provide equally strong evidence. Neither the footnote nor other studies' conventions should be changed.

### S08. Broader scope has positive evidence

Records 1–3 match S07. In record 4, Hana adds the version tag to a numeric table's title. In record 5, Idris rejects an otherwise identical removal from a second table and restores it. Source footnotes are unchanged throughout.

The actual world requires the title tag on charts and numeric tables in this workflow. The evidence supports that finite scope, not every conceivable visual or all documents.

| Same future task | S07 | S08 |
| --- | --- | --- |
| Create a numeric table title for the next snapshot L8 and retain the source footnote | NO CHANGE to untagged title, preserve correct provenance | ADAPT, add the current `L8` tag, not historical `L7` |
| Write a narrative paragraph about that snapshot with the established source reference | NO CHANGE, no exhibit-title syntax | NO CHANGE, no exhibit-title syntax |

S07 must retain the supported chart-only rule even though neither listed future task needs a title update. Candidate coverage and applied-update decisions therefore have separate denominators.

## Authoring and final-instance controls

- Keep observed diffs, provenance, authority and outcomes. Strip card IDs, pair names, expected actions, difficulty tags, author summaries and latent truth from model payloads. Use opaque record IDs and independently shuffled history order where chronology is irrelevant.
- Use one canonical field dictionary. Keep task family, worker role, recipient and workflow separate. Review equivalent scopes, candidate statuses and evidence-gap descriptions before freeze. Gold rule IDs are never valid shortcuts for predictions.
- Counterbalance which competing trigger is true, opaque names, endpoint direction, initial field presence and tag syntax through a recorded assignment schedule. Apply transformations jointly within each pair, preserving identical future inputs, the common-action control and the registered split of four update-required versus four retention-required diagnostics. Transform baselines and world policies together so a change in surface syntax does not change that split. Assert these invariants without model outcomes.
- Counterbalancing assigns new instances to the fixed eight variants; it does not add uncounted world cells. Transformations preserve S02's unresolved diagnostic, its baseline/world-policy disagreement and the seven-case completion-recoverability denominator. Keep assignments fixed across the three repetitions and record them with the generator seed. Swapped versions must receive the same pre-run validity review as the illustrations.
- Final histories and future tasks must be new instantiations after the protocol freeze. Future tasks use new records, contract values or snapshots and distinguish the paired histories' warranted decisions. The sales diagnostic uses an observed reviewer. Only designated cases require an unobserved combination of contextual features. Pair members intentionally share the current task to isolate the history contrast. This is within-structure transfer, not unseen-domain generalisation.
- Evaluate candidate scope across in-scope, out-of-scope and unknown contexts, including local exceptions and supported partial rules. Apply the same execution contract to all methods. An evidence gap stays an internal research artifact, not an employee question or a current-task prerequisite.
